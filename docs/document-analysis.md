# Document analysis model boundary

`GemmaDocumentAnalyzer` in `backend/app/ai/document_analysis.py` is a synchronous, database-free adapter. The caller supplies an owner-checked document UUID, its trusted kind (`resume`, `job_description`, `portfolio`, or `other`), and an ordered tuple of `DocumentChunkInput` values with canonical chunk UUIDs and exact extracted text. The model is never asked to invent document IDs, page locations, or hashes. The caller maps returned chunk IDs back to its own persisted document, locator, and hash and verifies ownership.

Each chunk is sent as untrusted user data in a separate bounded, structured-output request. Returned labels must be exact substrings of their exact source quotes, and quotes must be exact substrings of that supplied chunk. One nonblank character is valid. Every proposal retains its supplied document ID, kind and chunk ID. `suggested_state` (`have`, `want_to_learn`, or `unknown`) is an unconfirmed model suggestion, not an accepted fact; the adapter does not emit `excluded` or create public ReviewedItem IDs. Exact quotations establish provenance, not semantic correctness. The caller must present and explicitly confirm or correct suggestions before treating them as facts.

A valid `items: []` means the chunk produced no proposals, not a parsing failure. Success reports all processed chunk IDs, including chunks with no proposals. The adapter accepts at most 256 chunks, 12 proposals per chunk and 100 proposals total; labels are limited to 160 characters and quotes to 2,000. Exact duplicate items within a chunk fail; distinct citations across chunks or distinct states are preserved. The adapter preflights every chunk before sending a request. Empty/invalid input, non-UTF-8 text, excessive chunk/context size, malformed/truncated output, unsupported output fields, foreign IDs, fabricated text, duplicates, cancellation, HTTP errors and timeouts fail with a fixed `DocumentAnalysisError` code. An error exposes only the failed chunk ID and previously processed chunk IDs, and returns no partial result. The caller must not mark an incompletely processed document ready.

Construction can reuse the server-only question-model settings with `GemmaDocumentAnalyzer.from_question_settings()`; the explicit constructor accepts the same base URL, model, timeout, output-token and response-byte budgets. The default context-window budget is 8192 tokens and can be overridden explicitly to match the configured service. Input uses a conservative UTF-8 byte budget with space reserved for the prompt, output tokens and template overhead; over-limit input fails instead of being silently truncated. The model and transport do not log source text, model responses, prompts, credentials, or exception text. Model calls are sequential; this adapter does not own the shared execution lock.

Cancellation is checked before calls, after blocking I/O, before each chunk is recorded, and immediately before return. This cannot cancel an already-running remote GPU request or prevent a state change after return. The calling worker rechecks ownership, cancellation, lease, current document job, source hash, and source slices in its persistence transaction. Unrelated profile revision changes do not invalidate unchanged source analysis; publication advances the current revision. The adapter itself does not change document state, database records, retries, or user confirmation.

## Durable worker and review

Text and extracted TXT, DOCX, and text PDF uploads create a `document_analysis` job. From `backend`, run `uv run --env-file ../.env --locked python -m app.documents.worker` alongside the API (or add `--once` for one job). The module reads process environment variables; `uv --env-file` explicitly loads the repository-root configuration. The worker uses `RECOMMENDATION_MODEL_BASE_URL`, `RECOMMENDATION_MODEL_ID`, `RECOMMENDATION_MODEL_TIMEOUT_SECONDS`, `RECOMMENDATION_MODEL_MAX_TOKENS`, and `RECOMMENDATION_MODEL_MAX_RESPONSE_BYTES`; the existing `WORKER_LEASE_SECONDS`, `WORKER_MAX_ATTEMPTS`, and `WORKER_POLL_SECONDS` control leasing and polling. Model calls share the existing execution slot with question and recommendation workers. The worker is not started automatically by the API or `./dev`.

Each extracted source is split into bounded, source-located slices; nonblank slices are analyzed in full, sequentially. A document with more than 256 nonblank slices fails before any model call, without truncation; processing time grows with slice count. Failure, cancellation, invalid output, or incomplete coverage never publishes partial results. Leases, current document job, source hash, and exact chunk identities and content fence publication. Unrelated profile edits do not cancel independent document analysis; publication increments profile revision and invalidates dependent questions and recommendations. Deleted or retried sources cannot be resurrected by an older job. Legacy queued documents without jobs become retryable failures during migration, retaining their content and chunks.

Successful analysis stores server-generated review item IDs, immutable source quotation and locator/hash, `suggested_state`, and separate initially `unknown` user state. `PATCH /api/profiles/{id}/review-items` accepts `expected_revision`, editable `items` and optional `confirmed_document_ids`. When supplied, the document IDs are the exact set explicitly confirmed by the user; only ready, owned documents are accepted, including empty-result documents. Without that field an item change revokes its document confirmation. Pending, failed and unconfirmed documents block recommendation submission. The review token binds the confirmed source snapshot; reviewed have and want-to-learn states reach recommendation context and provenance, while unknown and excluded items do not become facts.

Synthetic provider tests exercise persistence and retry, but are not real model evidence. The endpoint exposes only a bounded extracted preview to the authenticated owner and never the private original file bytes.
