# File document registration

`POST /api/profiles/{id}/documents/files` accepts multipart fields `expected_revision`, `kind`, and `file`, with the same authenticated session, CSRF, revision, ownership, idempotency, and combined profile capacity rules as text registration. Accepted extensions are TXT, DOCX, and PDF, with matching MIME and file signatures; generic or absent MIME is accepted only with a matching format. Maximum original size is 5 MiB, extracted text is limited to 100,000 UTF-8 bytes, and PDFs to 50 pages. Limits reject rather than truncate. The current default is five combined text and file documents.

202 returns owner-visible document metadata; raw bytes and full chunks are excluded from the response. Original bytes and their exact SHA-256 are stored privately. Extracted text is stored in bounded source slices with paragraph/page character locators and a separate hash per slice. Successful extraction returns `queued` with a non-null analysis `job_id` and `review_confirmed: false`. The separately started document worker advances processing to `ready` or `failed`; ready responses include an owner-only extracted preview of up to 500 characters. Unsupported formats or mismatched signatures return 415 before persistence. Recognized but unreadable, encrypted, unsupported-content, image-containing, or scanned documents return `failed` with a sanitized `extraction_failed` code; originals are retained privately and no content is logged. OCR remains unsupported. To avoid silently omitting content, extraction rejects DOCX with drawings, text-bearing headers/footers, notes, tracked deletions, fields, or other unsupported objects, and PDFs with AcroForms, widget annotations, images, or Form XObjects. Unsupported documents can be converted to plain text before upload.

Analysis preserves immutable source quotes and locations in server-generated review items. The user edits labels/states and explicitly saves document confirmation before submission; a ready document with no proposed items also requires confirmation. Failed documents can be retried, and deletion removes their retained source and linked citations. See [document-analysis.md](document-analysis.md) for worker configuration and analysis limits and [document-lifecycle.md](document-lifecycle.md) for confirmation, retry, deletion, and validation.

Parsing occurs in a child with a CPU limit and ten-second timeout. Linux applies a 512 MiB address-space hard limit; on macOS, which does not support that limit, the parent samples RSS and kills the child above 512 MiB. Sampling cannot guarantee a hard peak memory ceiling. The parent also monitors RSS on Linux, bounds concurrent children per process to two, and fails closed if monitoring is unavailable. DOCX archive size, expansion, paths, XML declarations and entities are checked; PDF decoded content is bounded inside the monitored child. ZIP and PDF parsing failure details are never exposed.

## Reproduce

Apply the latest migrations, including `0011_document_analysis`, to a dedicated configured test database. From `backend`, run `L0_DATABASE_TESTS=1 .venv/bin/python -m unittest discover -s tests -p 'test_*documents.py'` and the lifecycle/worker tests linked above. These tests use synthetic inputs/providers. After authenticating, POST a synthetic UTF-8 `.txt` file with the three multipart fields above and the CSRF header; expect 202, `source_type: file`, `status: queued`, a non-null `job_id`, and `review_confirmed: false`. Start the document worker with the configured model, poll the job, then reload the owner profile to inspect and confirm its persisted items. OCR and URL extraction remain outside this flow.
