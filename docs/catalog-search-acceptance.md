# #25 현행 Work24/BGE 검색 수용 기준

2026-11-01 사용자는 PR #82 리뷰에서 지적한 옛 FTS/NCS/RRF 설계와의 차이를 정리할 때 **현행 Work24/BGE를 기준으로 명세를 정리**하도록 선택했다. 따라서 이 문서는 검색 엔진을 교체하는 계획이 아니라, 이미 구현된 내부 교육 후보 검색의 완료 기준을 기록한다. 자료 API·문서 분석·추천 생성은 다른 작업 범위다.

## 기존 설계와의 차이

| 이전 요구 | 현재 합의한 동작 | 구현·검증 근거 |
| --- | --- | --- |
| 한국어·영문 용어 정규화 및 사전 버전 | 질의를 변경하지 않고 고정 BGE-M3로 임베딩한다. 별도 사전 없이 평가셋·임베딩 프로필·모델 revision·검색 버전을 기록한다. | `app/catalog/service.py`, `repository.py`; 원문 공백·개행 보존 테스트, 한국어·한영 혼합 실제 질의 평가 |
| PostgreSQL FTS/GIN | 활성 스냅샷 전체 단위에 대한 pgvector cosine exact 검색 | `CatalogRepository.search`, 독립 SQL 전체 후보 oracle |
| NCS 링크 검색 채널 | NCS는 원천 코드와 출처·추정 여부를 가진 근거 메타데이터다. 별도 후보 검색 채널로 사용하지 않는다. | `UnitEvidence`, inferred/provenance 보존 테스트 |
| title/body/NCS 순위를 RRF로 결합 | 과정별 가장 높은 단위 유사도, 조건에 맞는 최선 회차, 과정 순서로 집계한다. 버전은 `work24-exact-max-v1`이다. | 검색 집계·동점·정확한 원천 ID 테스트 |
| 빈 채널 간 fallback | 단일 dense 경로에서 빈 카탈로그·조건 필터로 인한 빈 결과·질의/모델/DB 오류를 구분한다. 다른 모델이나 저장 벡터로 대체하지 않는다. | 검색·임베딩 계약 검사와 명시적 오류 |
| 안정적 중복 제거 | 정확한 source course ID 기준으로 한 과정을 반환한다. 이름이 같다는 이유로 다른 과정을 합치지 않는다. | 다중 회차·동점·`1`/`01` 경계 검사 |

FTS·NCS 검색·RRF 신규 도입은 이번 완료 조건이 아니다. 실제 품질 결과를 바탕으로 도입 필요성과 계약 변경을 별도 검토할 수 있다. 이 결정은 기존 검색의 부재 질의 탐지·정밀도를 입증하지 않는다.

## 원천 판정 표본 정책

실제 결과의 각 질의 상위 3개 과정, 총 60쌍을 표본으로 선택한다. 이 표본은 검색 상위 결과에 편향되어 있으며 전체 카탈로그의 무작위 표본이 아니다. 두 검토 에이전트에는 순위·점수·기존 라벨을 제거하고 해시 순서로 섞은 쌍과 고정 원천 파일만 제공한다. 원천 과정의 명시적 목적과 비추정 단위를 기준으로 독립 판정한다.

두 검토가 같은 판정에 도달했고 정확한 원천 발췌가 검증되는 경우에만 관련/무관으로 반영한다. 의견이 다르거나 질의 자체가 넓고 모호한 경우, 원천이 불충분하거나 비용·일정 조건을 확정할 수 없는 경우는 미판정이다. 검토자 기록은 모델이 수행한 원천 검토이며 사람 전문가의 정답으로 주장하지 않는다. 발췌가 존재한다는 사실은 의미 판정의 객관적 참을 증명하지 않는다.

사후 표본 판정으로 원래 기대셋 Recall/MRR을 재작성하거나 새로운 비편향 벤치마크를 주장하지 않는다. 표본 밖 540쌍은 검토하지 않았으므로 미판정이다. 부재 질의의 일부 반환 과정을 무관하다고 판정해도 코퍼스 전체에 관련 교육이 없다고 결론 내릴 수 없다.

## 최종 검증 기록

2026-11-01 현재 PR 작업 트리에서 `./check`가 exit 0으로 완료됐다. 환경은 Python 3.14.6, Node 26.5.0, 독립 PostgreSQL 16.14/pgvector 0.6.0이다. 고정 패키지를 전용 DB에 적재했으며 다른 가지 DB를 사용하지 않았다.

| 검사 | 결과 |
| --- | --- |
| 웹 타입·린트·포맷·테스트 | 통과, 테스트 276개 |
| 백엔드 | 331개 통과, 선택 실행 2개 제외 |
| launcher | 22개 통과 |
| 카탈로그 단위 | 32개 통과 |
| 카탈로그 통합 | 13개 통과, 선택 실행 3개 제외 |
| 웹 production build | 통과 |
| 검색 계약·실제 DB 집중 검사 | 20개 통과, 새 40과정/150단위 혼잡·비활성 단위/과정·한도 검증 포함 |

새 회귀는 최종 한도 30보다 많은 40개 활성 과정과 한 과정의 150개 단위가 있어도 다른 과정이 밀려나지 않는지 확인한다. 더 높은 점수의 비활성 단위와 비활성 과정은 포함되지 않고, limit/evidence limit 경계 밖 입력은 거부된다. 실제 GPU로 측정한 검색 품질과 합성 벡터로 확인한 SQL/계약 정합성은 서로 다른 검사다.

[전체 검사 및 정리 기록](evaluations/work24-source-review-2026-11-01/verification.json)에 현재 작업 트리의 테스트 파일 해시와 결과를 보존했다. 기존 opt-in 5개는 실행하지 않았다: CI 전용 재적재 검사, 독점 ACL 환경이 필요한 추천 DB 거부 검사, 별도 빈 DB를 요구하는 records/legacy 검사 3개다. 이는 이번 검색/평가 변경의 계약 검사와 구분한다. CI를 켜거나 테스트 조건을 약화하지 않았다. 변경한 검색 계약/SQL 검사는 별도 실행에서도 모두 통과했다. 기존 실검색을 반복해 좋은 결과로 교체하지 않았으며, 이번 PR은 저장된 실검색 결과를 원천과 대조했다.

GitHub Actions와 스케줄러는 사용자 요청으로 비활성 상태를 유지한다. 운영 GPU/DB 설정과 자료 API·모델·추천 Worker를 변경하지 않았다.
