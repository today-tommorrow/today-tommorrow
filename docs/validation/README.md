## 이번 문서 정리와 제품 검증의 경계

이번 작업은 문서 분류·링크·계약 참조·이슈 추적을 검증합니다. 실제 Google OAuth, 원천 데이터 적재, 업무 Alembic 적용, 모델 추론, GPU 성능, 다른 물리적 Mac을 검증한 것으로 표시하지 않습니다. 원본 패키지의 검증 기록도 작성 당시 수행/미수행 내역이며 현재 제품의 통합 성공 증거가 아닙니다.

2026-11-01 분류 검증: 로컬 상대 링크 338개(HTML fragment 포함), 원본 25개와 재배치본의 manifest 해시, OpenAPI 내부 참조 307개, SQL/ERD 테이블 23개, 이슈 초안 26개의 필수 항목과 의존성 순환 여부를 확인했고 오류는 없었습니다. `git diff --check`도 통과했습니다. 공식 OpenAPI validator·YAML parser·TypeScript compiler·Mermaid 엔진·브라우저 실행은 이번 문서 작업에서 실행하지 않았습니다.

재현 시 [source manifest](../reference/source-manifest.json)의 각 destination SHA256을 파일과 대조하고, 변환 없는 파일은 source SHA256과도 일치하는지 확인합니다. Markdown/HTML의 상대 링크 대상과 HTML fragment를 검사하고, OpenAPI JSON의 모든 `$ref`가 같은 파일 안에서 해석되는지 확인합니다. SQL의 CREATE TABLE 목록과 Mermaid ERD 엔터티, issue-plan.json의 선행 ID와 각 이슈 본문 참조가 일치하는지도 확인합니다. 개인 `.docs.local` 원본이 없는 새 클론에서도 destination 해시·링크·계약 참조 검사는 가능합니다.

## 구현 PR의 필수 기록

- 실행 명령 또는 재현 절차, 합성/공개 허용 샘플, 예상·실제 결과, 런타임·DB·모델·장치 버전, 미실행 항목과 이유.
- 목(mock), 실제 모델 CPU, 실제 GPU를 별도로 기록. GPU가 범위 밖이면 N/A와 이유.
- DB 변경은 Alembic 적용 후 저장·재조회와 이전 데이터/API 영향 확인.
- 실제 모델이 완료 조건이면 같은 샘플로 웹 → API → 모델 → 결과 표시 확인.
- 실제 PR에서 CI 성공 후 필수 검사 지정. 자동 승인·자동 배포는 제외하고 사람이 검토.

## 통합 검증 시나리오

| 흐름 | 확인할 결과 |
| --- | --- |
| 자료 없음 | 로그인, 선택 질문, 미정·온라인 분기, 전체 확인, 실제 추천까지 완료 |
| 자료 있음 | 파일/OCR·공개 링크·텍스트 실제 추출, 인용 확인·수정 후 제출 |
| 수정·동시성 | 중복 선택 1회 적용, 임의 옵션·타인 자료 거부, 오래된 revision 409, 최신 답변 보존 |
| 실패 복구 | 질문 fallback 구분, 자료 재시도·삭제, Worker 복구, 추천 실패를 성공 카드로 대체하지 않음 |
| 데이터 | 부분 배치 누락으로 삭제하지 않음, 잘못된 배치 격리, 이전 추천의 버전 보존 |
| 배포 | HTTPS·쿠키, SPA 새로고침, 정상/없는 API, 없는 정적 자산 404, 수동 복구 |
| GPU 품질 | JSON 유효율·수정률·의미 일치·반복 질문·검색/추천 근거 품질·p50/p95·큐 대기·기아·메모리 |

성능·품질 수치는 아직 합격 기준이 아닙니다. 평가셋과 목표치를 먼저 합의하고 실제 L4에서 측정한 결과로 판정합니다.
