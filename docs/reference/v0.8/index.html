검색과 후보 구성 · S3

추가된 데이터를 포함한 활성 카탈로그의 전체 색인을 검색한다. 모든 교육 원문을 매번 Gemma 프롬프트에 넣지 않는다. 기본안은 PostgreSQL과 기존 Gemma를 사용하며 별도 임베딩 모델·벡터 DB 도입을 필수로 가정하지 않는다.

검색 경로입력과 처리유의점
제목·용어사용자 표현과 확인된 동의어를 정규화해 title_terms 검색.한국어 공백·영문 표기·동의어 사전을 버전 관리. simple FTS를 한국어 의미 이해 모델로 표현하지 않는다.
설명·학습내용본문에서 실제 확보한 body_terms와 학습 필요 용어 검색.목록에 제목만 있으면 본문 근거를 만들어 채우지 않는다.
NCS 연결관련 NCS 참조에 연결된 course_skill_links 검색.content_supported / topic_only / suggested를 보존. 모델 연결은 실제 커리큘럼 증거가 아니다.
질의 보완Gemma가 사용자 목표를 source vocabulary와 연결한 검색어 후보 제시.원문 목표와 연결 근거가 있는 확장만 사용. 질의 보완은 지역·예산·시간 제약 완화가 아니다.
순위 결합서로 다른 경로의 순위를 RRF로 합치고 course/회차 ID 기준 중복 정리.채널에 없는 문서는 해당 채널 점수 0. 한 채널이 비었다고 실패하지 않는다. 모든 경로가 비면 데이터 범위/검색어 근거를 확인해 빈 결과 분류.
RRF(c) = Σ_channel 1 / (k + rank_channel(c))
초기 설정 제안: k=60, 경로별 최대 100, 융합 뒤 내용 평가 최대 30.
반환 순서는 동일 점수일 때 source/course/offering ID로 고정.
후보 수는 고정 표본 수와 무관하며 설정 파일로 조정한다.

색인은 정규화한 제목·본문 용어를 to_tsvector('simple', ...)로 구성하고 GIN index를 사용한다. 입력 검색어는 구조화·정규화 후 parameterized query로 전달한다. 한국어 형태 변화 대응은 버전 관리하는 용어 사전과 검색 평가가 필요하다. 사용자 텍스트를 SQL이나 도구 명령으로 실행하지 않는다.

현재 기본안의 검색 품질을 실제 확장 데이터로 평가하고, 필요한 경우 후속 검색 방식을 비교한다. 이 개정에서는 새로운 임베딩 모델이나 성능 수치를 확정하지 않는다.

참여 조건 검증 · S4

fail = 확인된 충돌, unknown = 판단할 근거 부족이다. unknown을 탈락이나 통과로 바꾸지 않는다. “맞는 교육이 없다”는 이유로 조건을 자동 완화하지 않는다.
조건pass / fail을 판단할 근거unknown 처리
모집·시작 일정검증된 단위의 enrollment/end와 as_of, 명시된 모집상태. 현재 회차가 종료됨이 확인되면 제외.목록의 모집중 표시만으로 현재 신청 가능 확정 금지. 강좌 접근 가능 여부와 모집 접수 여부를 구분.

방식·지역확인된 온라인/대면/혼합, 실제 교육장 위치와 사용자가 허용한 통학 범위.기관 주소만으로 모든 회차 교육장을 확정하지 않음. 온라인만 선택한 사용자의 통학은 N/A.
예산확인된 개인 부담액 또는 지원과 무관하게 적용되는 확정 수강료가 예산을 넘으면 fail.표시 자비부담금만 있으면 개인 최종 부담은 unknown. estimated_cost는 참고로 표시하고 근거 없는 지원금 차감 금지.
자격·선수지식명시된 참여자격과 사용자가 확인한 사실이 분명히 충돌할 때 fail.고용·학력·나이 미입력이나 조건 문구가 모호하면 unknown. 문서가 침묵한다고 불충족으로 간주하지 않음.
시작 희망사용자가 hard 제약으로 확인한 날짜 범위만 제외 조건. “가능하면 바로” 등 기본 선택은 soft preference.시작 시점 미정은 일정 검사를 생략한 unknown으로 기록.

규칙 결과는 field, status, reason_code, evidence_ids로 저장한다. 예: SCHEDULE_CONFLICT, RECRUITMENT_CLOSED, PERSONAL_PRICE_UNKNOWN, COURSE_LOCATION_UNKNOWN. 정보 신선도가 기준 밖이면 확정값의 유효성을 낮추고 재확인 필요를 표시한다. 갱신주기는 원천별 운영 설정으로 관리한다.

각 축은 0 / 0.5 / 1 / null이다. 1은 명확한 연결, 0.5는 부분 연결, 0은 근거로 확인되는 비연결, null은 근거 부족이다. 0과 null 모두 설명 근거를 구분해 저장한다. 특히 학습 결과가 원문에 없다는 이유만으로 “프로젝트가 없는 과정”이라고 쓰지 않는다.
