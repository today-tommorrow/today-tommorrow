## 연동 계약

GET /api/jobs/{id} → Job. status는 queued/running/succeeded/failed/superseded/cancelled; phase=completed와 status=succeeded를 구분. 성공 result는 kind별 ID만 반환하고 추천 완료 전 후보는 노출하지 않는다.

합성/공개 사용 허용 샘플만 사용한다. 예시는 필드 중심이며 전체 필수 필드·타입·HTTP 상태는 연결된 계약을 따른다. 성공/오류/빈 결과의 완전한 요청·응답 fixture를 구현 PR에 기록하고, 변경 전후 예시를 관련 영역과 확인한다.

- [ ] 질문 우선 처리와 추천 작업 기아 방지·공유 GPU 동시성 검증
- [ ] 소유권·멱등·실패 재시도 규칙을 확정하고 검증
- [ ] 실행 명령/재현 절차, 샘플, 예상·실제 결과, 환경·버전, 미실행 항목과 이유 기록.
- [ ] 필요한 기존 검사 `./check` 및 해당 기능의 계약/통합 검사 통과.
- GPU: **공유 GPU 동시성·대기 검증 필요; 상태 전이 단위 검사는 목과 별도 기록**. 목·실제 모델 CPU·실제 GPU 결과를 구분한다.
