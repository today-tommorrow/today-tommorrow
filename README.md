# today-tommorrow

## 해커톤 협업 규칙

`main`은 웹, API, AI가 함께 동작하는 데모 기준 브랜치다. 각 작업은 최신 `main`에서 분기하고, 팀원이 확인할 수 있는 작은 단위로 PR을 연다.

### 브랜치 이름

`<종류>/<영역>/<작업>` 형식을 사용한다. 작업 이름은 짧은 영문 소문자로 쓰고 단어는 하이픈으로 연결한다.

| 예시 | 용도 |
| --- | --- |
| `feat/web/result-view` | 샘플 응답으로 결과 화면 구현 |
| `feat/api/predict` | 예측 요청 처리와 오류 응답 구현 |
| `exp/ai/model-v2` | 후보 모델의 추론 결과 비교 |
| `feat/ai/inference` | 채택한 모델을 추론 코드와 연결 |
| `fix/api/input-validation` | 입력 검증 오류 수정 |

영역별 상설 브랜치는 두지 않는다. 모델 실험에서 채택된 변경만 최신 `main` 기준으로 정리해 PR을 연다.

### 영역 간 연동

1. 연동을 시작할 때 요청 필드, 모델 입력 형식, 성공·오류 응답을 정하고 팀이 함께 쓸 샘플 입력과 예상 응답을 PR에 기록한다.
2. 웹은 샘플 응답으로 화면을 만들고, API와 AI는 같은 예시로 구현을 확인한다. 계약을 바꾸면 영향을 받는 영역 담당자에게 리뷰를 요청하고 변경 전후 예시를 남긴다.
3. 실제 모델을 연결한 PR에서는 같은 샘플을 웹에서 입력해 API와 모델을 거쳐 결과가 표시되는지 확인하고 결과를 PR에 남긴다.

### PR과 병합

- PR 대상은 `main`이다. PR 본문에 변경 목적, 영향받는 영역, 실행한 검증과 결과를 적는다.
- `main` 변경은 관리자도 PR을 거친다. 필수 승인 수는 0명이며, 계약 변경 리뷰 요청은 팀의 협업 규칙이다.
- 병합은 **Squash and merge**를 사용한다. 병합 후 작업 브랜치는 자동 삭제된다. `main`의 강제 푸시와 삭제는 차단한다.
- 초기에는 필수 CI 검사를 지정하지 않는다. 팀의 검사 워크플로가 실제 PR에서 한 번 이상 성공한 뒤 해당 검사를 필수로 지정한다.
